The kitchen now has all three activities from the concept. On the start screen the child chooses **Listen and find**, **Look and identify**, or **Recall and spell**. ## What Was Built

### Core rules (#42, #44)

`src/core/exercise.js` now has one shared round controller (selection without repeats, never the same object twice in a row, *try again*, then *reveal* after 2 wrong answers). The three activities are built on it:

- `createListenAndFind`: unchanged behaviour; the answer is a tapped object ID.
- `createLookAndIdentify`: each challenge has `choices`, the target plus up to 3 distractors from the same room, in shuffled order. A distractor never shares a spelling (label or accepted spelling) with the answer, and two distractors never share one either, so exactly one button is right. With fewer words in a room, fewer choices are offered; a target with no possible distractor is an error.
- `createRecallAndSpell`: the typed text and every accepted spelling are normalised with `normalizeAnswer` (trimmed, lowercased, repeated spaces collapsed), then compared. The label always counts as accepted. There is no typo tolerance.

Each exercise reports its `activity`, and so does the session (`session.activity`). The session now passes any answer (an object ID or typed text) through to the exercise.

### Game

`RoomScene`:

- In the two new activities, the target object glows blue (the existing cut-out and halo) with a pulsing blue ring. If an object appears more than once, all its instances glow.
- Taps on the room are ignored in these activities; only Listen and find answers by tapping.
- After a wrong answer the target keeps glowing. After a correct answer or a reveal, it shows the same green or yellow feedback as Listen and find.

### Shell (#41, #43, #45)

- **Start screen:** three large buttons with a simple line icon (ear, eye, pencil) and a label. They replace the *Start* button and load the room on first use.
- **Look and identify:** prompt *"What is this?"* and large word buttons in the HUD. A wrong word is crossed out and disabled. A correct word turns green. On a reveal, the right word gets a yellow border.
- **Recall and spell:** prompt *"What is this? Type its name."*, a large text box with a *Check* button, and Enter to submit. `autocomplete`, `autocorrect`, `autocapitalize`, and `spellcheck` are off. The box is focused at each challenge. After *try again* the text stays selected, so the child can type again at once. A reveal fills in the correct spelling (*"It's spelled: refrigerator"*). An empty box is ignored rather than counted as wrong.
- **Summary:** *"You found / named / spelled 8 out of 10."*, with *Play again* and *Change activity*.
- The controls sit in the side panel on wide screens and in a row under the prompt on narrow ones.

### Tests

- Unit: `tests/unit/look-and-identify.test.js` and `tests/unit/recall-and-spell.test.js` cover choice count, distractor rules, shuffling, reproducibility, normalisation, accepted variants, multi-word labels, the lack of typo tolerance, and retry/reveal. `session.test.js` covers typed answers.
- Test bridge: `state` now includes `activity`, `choices`, and `highlighted` (the glowing object). A new `word(objectId)` returns its label and accepted spellings, so tests never hardcode words.
- End-to-end, Look and identify: the target glows and taps are ignored, a correct word scores, a wrong word is crossed out, two wrong words reveal the right one, and a full round is followed by *Change activity*.
- End-to-end, Recall and spell: the input attributes, focus, a correct spelling submitted with Enter (in any case, with extra spaces), an accepted variant (*fridge*), an empty box being ignored, a wrong spelling, and a reveal.
- The existing tests now start Listen and find with its activity button.
