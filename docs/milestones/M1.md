## Summary

The game is playable. In a laptop/PC browser, the child presses **Start**, reads a written prompt such as *"Find the refrigerator."*, and clicks the object in a placeholder kitchen. Each answer gets immediate feedback, the HUD shows the score and time, and after 10 challenges a summary offers *Play again*. There is no audio yet (M3).

## What Was Built

### Content (#9, #10)

- **Placeholder kitchen** in `content/rooms/kitchen/`: `room.png` (2048 × 1536) and 10 masks for 9 objects: refrigerator, stove, sink, cupboard, window, clock, table, cup, and two chairs (`chair@1`, `chair@2`). It includes a repeated object (chairs), small objects (cup, clock), and occlusion (the cup sits in front of nothing interactive; the right chair hides part of the stove, so the stove's mask has a hole).
- `tools/make-placeholder-kitchen.js` (`npm run make:placeholder-kitchen`) draws the painting and masks from simple vector shapes. Masks are rendered without anti-aliasing, minus objects in front, so they never overlap.
- **JSON Schemas** in `content/schemas/` for the lexicon and room manifests.
- `content/lexicon.json` (9 words, with prompts such as *"Find a chair."* and accepted spellings such as *fridge*) and `content/rooms/kitchen/manifest.json`.
- `src/core/content-validation.js` validates with Ajv and adds cross-checks (unknown or duplicated objects, accepted spellings shared by two objects in a room). `src/core/content.js` joins a manifest with the lexicon for the game.

### Room build (#11)

`npm run build:rooms` (`tools/build-rooms.js`, algorithms in `tools/lib/room-build.js`) runs automatically before `dev` and `build`. For each room it writes to `public/assets/rooms/<room>/` (git-ignored):

| File | Content | Kitchen size |
|------|---------|--------------|
| `background.webp` | The painting | 21.7 KB |
| `hitmap.bin` | Instance index per pixel at 1024 × 768, run-length encoded | 17.9 KB |
| `layout.json` | Each instance: index, name, objectId, bounds, tap point | 2.4 KB |

It fails with a clear list of problems on schema errors, unknown objects, badly named, missing, extra, wrongly sized, empty, or overlapping masks. For example:

```
build:rooms failed. Room "kitchen" is invalid:
- mask "Cup_bad.png" is not named <objectId>.png or <objectId>@<n>.png
- object "cup" has no mask
- masks "sink@2" and "table" overlap on 54672 pixels
```

Tap points are the pixel farthest from the region's edge, nearest its centroid on ties.

### Core rules (#12–#15)

All in `src/core/`, plain JavaScript with no Phaser or DOM dependency:

- `rng.js`: seedable mulberry32 generator with `next`, `int`, and `shuffle`.
- `hitmap.js`: run-length encode/decode, `instanceAt` lookup in logical coordinates, and logical ↔ screen conversion.
- `exercise.js`: Listen and find. 10 challenges per round, no object repeated while unused ones remain and never twice in a row, *try again* after a wrong answer, *reveal* after 2 wrong answers.
- `session.js`: score (`correct / attempted`, where *attempted* counts ended challenges), elapsed time, and events `challengeStarted`, `answerEvaluated`, `roundEnded`.
- `events.js`: a minimal event emitter.

### Game (#16, #17, #19)

- Scenes in `src/game/scenes/`: `Boot` (no assets yet), `Preload` (loads a room's files with a progress bar), and one generic `RoomScene` that displays any room from its generated files.
- Clicks use Phaser pointer events only (mouse and touch share one path). Clicks on walls, floor, or decorations are ignored.
- **Feedback** is drawn from the hit map, so it follows the object's real shape:
  - correct: green highlight that pulses
  - try again: orange highlight that fades out
  - reveal: yellow pulsing highlight on every instance of the object, plus a ring
- `?debug=hits` (`src/game/debug-hits.js`) shows each hit region in its own colour with its instance name. Available in dev and test builds only.

### Shell (#18)

`index.html`, `src/shell/shell.js`, and `src/shell/style.css`:

- Start screen, loading screen, and round summary (*"You found 8 out of 10."*, time, *Play again*).
- HUD with the written prompt, feedback message, *correct / attempted*, and elapsed time.
- The HUD is a side panel on wide screens and a top bar on narrow ones.

`src/app.js` connects shell, game, and core: it loads the room, runs rounds, updates the HUD from session events, and waits 1.2 s after a correct answer (2.4 s after a reveal) before the next challenge.

### Tests and CI (#20)

- **Test build:** `npm run build:test` builds with `--mode test` into `dist-test/`. Only this build contains the test bridge and the debug overlay; a check of the production bundle confirmed neither is present.
- **Test bridge** (`src/test-bridge/bridge.js`), exposed as `window.__wordsTest`: current screen, challenge and score; each instance's tap point in screen coordinates; logical-to-screen conversion; and an RNG seed setter.
- **End-to-end tests** (Chromium), run by `npm run test:e2e`:
  - start screen shows over the canvas
  - the canvas keeps its 4:3 shape and rescales
  - a click on the wall is ignored, a correct answer scores **1 / 1**, a wrong answer shows *try again* with the score unchanged
  - two wrong answers reveal the object and score **0 / 1**
  - a full round of 10 ends with *"You found 10 out of 10."* and *Play again* starts a new round
- CI (`.github/workflows/ci.yml`) is unchanged: `npm run build` now runs `build:rooms` first, and `npm run test:e2e` uses the test build.

## Deviations from the Plan

- **The placeholder kitchen is drawn by a script, not AI-generated.** Image generation isn't available in this workflow, so `tools/make-placeholder-kitchen.js` draws a flat vector kitchen and its masks. This is enough to build and test the whole pipeline. The AI-generated kitchen with ~50 objects is part of M2.
- **`hitmap.bin` instead of `hitmap.png`.** A run-length encoded binary file avoids browser colour management altering index values when a PNG is decoded, and its decoder is unit-tested in Node. `TECHNICAL.md` was updated.
- **Separate test build.** The end-to-end tests run against `dist-test/` (production code plus the test bridge), so the production build stays free of test code. `TECHNICAL.md` §8 was updated.
- **Lexicon and manifests are bundled** with the game code (imported as JSON) rather than loaded as separate files. They are small, and `build:rooms` validates them before every build.
