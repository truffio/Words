## What Was Built

### Game project (#2)

- Started from Phaser's official Vite template ([phaserjs/template-vite](https://github.com/phaserjs/template-vite)), then simplified to a single `vite.config.js`.
- **Fixed logical resolution of 2048 × 1536** (4:3), defined once in `src/core/display.js` and scaled to the window with Phaser's `Scale.FIT`, centered.
- A temporary `Boot` scene (`src/game/scenes/Boot.js`) draws a frame and the title *Words*, so scaling can be seen. M1 replaces it with the Boot / Preload / RoomScene flow.
- Entry point `src/main.js`; page styles in `src/shell/style.css`.

### Code quality (#3)

- ESLint 10 flat config (`eslint.config.js`): recommended rules, browser globals for game code, Node globals for configs, tools, and tests, and `eslint-config-prettier` to avoid conflicts.
- Prettier (`.prettierrc.json`): single quotes, 100-character lines. Markdown documents are excluded so the design documents keep their hand formatting.
- `.gitattributes` keeps LF line endings in the working copy on Windows, so formatting checks give the same result locally and in CI.

### Unit tests (#4)

- Vitest runs `tests/unit/**/*.test.js` in Node.
- One test checks the logical resolution. Real core tests arrive in M1.

### End-to-end tests (#5)

- Playwright with a Chromium project (`playwright.config.js`), tests in `tests/e2e/`.
- `npm run test:e2e` builds the game, serves it with `vite preview` on port 4173, and runs the tests.
- Smoke test (`tests/e2e/smoke.spec.js`): the canvas appears, fills the height of a wide window and the width of a tall window, and keeps its 4:3 shape.
- Screenshots and traces are kept on failure.

### Continuous integration (#6)

`.github/workflows/ci.yml` runs on every push and pull request:

1. Check out, set up Node LTS with the npm cache, `npm ci`
2. `npm run lint`
3. `npm run test`
4. `npm run build`
5. Install Chromium, `npm run test:e2e`
6. On failure, upload the Playwright report and test results

### Project structure (#7)

The folders from [TECHNICAL.md §9](../../TECHNICAL.md#9-project-structure-proposed) are in place, with `.gitkeep` files in empty folders: `content/schemas`, `content/rooms`, `public/assets/shared`, `src/core`, `src/game`, `src/shell`, `src/test-bridge`, `tools`, `tests/unit`, `tests/e2e`. Generated room assets (`public/assets/rooms/`), build output, and test output are git-ignored. The [README](../../README.md) explains the layout and the npm scripts.

## Deviations from the Plan

- **Template telemetry removed.** Phaser's template includes a `log.js` script that contacts a Phaser server on every `dev` and `build`, and a promotional build message. Both were left out.
- **End-to-end test already runs in CI.** Issue #6 planned this for M1. The smoke test existed and adds only a few seconds, so it was included now.
- **No `vite/` config folder.** The template's separate dev and production configs were merged into one `vite.config.js`, as in the planned project structure. The template's Terser setup and manual Phaser chunk were dropped; Vite 8's default minifier is used.
